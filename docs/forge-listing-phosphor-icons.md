# Forge listing copy — Phosphor Icons for OutSystems 11

Paste-ready metadata for submitting `dist/o11-phosphor/` to the OutSystems Forge.
Hand-authored — **not** generated by `tools/phosphor_o11.py`, so it survives a
regeneration of the pack.

Facts this copy is built on, all verified against the pack: Phosphor Regular
2.1.2, **1,530 icons**, MIT licensed, single webfont (147 KB woff2), size
helpers `ph-16` / `ph-20` / `ph-24` / `ph-32`, font embedded as base64 so no
Resource is required.

---

## 1. Asset name

**Primary:**

    Phosphor Icons

**Fallbacks if that name is taken** (Forge names are unique):

    Phosphor Icons Font
    Phosphor Icon Pack
    Phosphor 1530 Icons

Do **not** list it as `NeoPhosphor`. Nobody searches for that. The one word
carrying all the search traffic is *Phosphor*, and it must be the first word in
the name — Forge's own search is essentially a name-and-tag match, so a leading
brand keyword outranks anything you put in the description.

Keep "for OutSystems 11" out of the *name* if the field is short; every Forge
asset is for OutSystems, so it spends characters without earning any ranking.
Put the platform in the summary instead.

## 2. Summary / short description

The single highest-value field: it is what shows on the search-results card and
what search engines use as the snippet. Front-loaded with the keywords, 147
characters:

    1,530 Phosphor icons as a webfont for OutSystems 11. One theme paste, no
    resources, four sizes. MIT licensed. Reactive, Mobile and Traditional Web.

If the field is tighter than that, in order of what to drop: the platform list,
then the licence, then the sizes.

Shorter variant, 89 characters:

    1,530 Phosphor icons as a webfont for OutSystems 11 — one theme paste, no
    resources, MIT.

## 3. Tags / keywords

Forge tag fields are usually comma-separated and capped, so these are ordered by
value. **Use the first five if you can only have five.**

    phosphor, icons, icon, webfont, font-icon

Then, in order:

    icon-library, icon-pack, icon-set, ui, theme, css, svg-alternative,
    open-source

Notes on the choices:

- `icons` **and** `icon` both earn their place — Forge search does not stem, so
  the singular and plural are genuinely different queries.
- `webfont` and `font-icon` are what people type when they have hit the "my SVG
  sprite won't theme" problem and are looking for the font approach.
- `svg-alternative` is deliberate long-tail: it catches the search that starts
  from the problem rather than the solution.
- Skip `outsystems`, `o11`, `reactive`, `forge`. Every asset on the Forge is all
  of those, so they carry no discriminating power and just dilute the set.

## 4. Category

    UI / Front-end (or "Themes & Icons" if that option exists)

Not "Library" — it ships CSS and a font, not server logic, and the people
looking for it are browsing the UI shelf.

## 5. Long description (markdown, paste as-is)

> ### 1,530 Phosphor icons for OutSystems 11
>
> [Phosphor](https://phosphoricons.com) is a flexible, MIT-licensed icon family
> with a clean, neutral line style that sits comfortably next to OutSystems UI.
> This asset brings the complete **Regular weight — 1,530 icons** — into
> OutSystems 11 as a single webfont.
>
> **OutSystems Developer Cloud already serves Phosphor on every page. OutSystems
> 11 does not.** Drop Phosphor markup into an O11 app and you get nothing at
> all — no font, no glyph, blank space. This asset is what closes that gap, so
> the same icon names work on both platforms and a design system can span them
> without forking its icon set.
>
> ### Install
>
> Paste one stylesheet into your Theme and publish. That is the whole install.
>
> The font travels inside the CSS as base64, so there is **no Resource to add,
> no Deploy Action to set, and no asset path to get wrong** — which is the usual
> way an icon font import fails, and it fails silently. A smaller linked variant
> is included too if you would rather cache the font separately.
>
> ### Use
>
> ```html
> <span class="ph ph-cube ph-20"></span>
> ```
>
> `ph` loads the font, `ph-<name>` picks the glyph, and the size helper sets
> `font-size` — a font icon is sized by `font-size`, not `width`/`height`, which
> is the single most common mistake when moving over from an SVG icon set.
>
> Sizes: `ph-16`, `ph-20`, `ph-24`, `ph-32`. Colour follows `color`, because the
> glyph is text:
>
> ```html
> <span class="ph ph-warning ph-24" style="color: red"></span>
> ```
>
> Size helpers are named in explicit pixels rather than `icon-small` / `pds-icon`
> so they cannot collide with OutSystems UI.
>
> ### Works with OutSystems UI
>
> OutSystems UI uses `.ph` to mean *placeholder* and hides empty ones with
> `.ph:empty { display: none }`. A font icon is empty by design — the glyph comes
> from `::before` — so a naive Phosphor import is hidden on every page, at 0×0,
> with the font loaded and nothing in the console. This asset ships the override
> that resolves that collision, scoped so genuine placeholders stay hidden.
>
> ### What's included
>
> - 1,530 Regular-weight icons
> - One 147 KB woff2 webfont
> - Four size helpers
> - `icon-names.txt` — every icon name, one per line
> - Browse the icons visually at [phosphoricons.com](https://phosphoricons.com)
>   (set the weight to Regular)
>
> ### Compatibility
>
> Reactive Web, Mobile and Traditional Web. No dependencies, no server actions,
> no extensions — just CSS and a font.
>
> ### Licence
>
> Phosphor Icons is MIT licensed, © 2020–2021 Phosphor Icons. The full licence
> text ships with the asset.

## 6. Two things to sort out before you submit

1. **A Forge asset has to be a module, not a folder of CSS.** Forge distributes
   OML/OSP packages, so the pack needs wrapping in an O11 theme module — the
   stylesheet in the Theme, `icon-names.txt` and `LICENSE` as Resources. See
   [o11-theme-module.md](o11-theme-module.md). Worth adding a demo screen with a
   searchable icon grid: on the Forge, a screenshot of the icons is worth more
   than any of the copy above.

2. **Attribution is a licence condition, not a courtesy.** MIT requires the
   copyright notice and licence text to travel with the work. Keeping `LICENSE`
   in the module and the credit line in the description satisfies it. Also say
   plainly in the description that this repackages upstream Phosphor and is not
   affiliated with the Phosphor project.
