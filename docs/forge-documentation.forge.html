Before you start

Neo Design System requires the TrueShade component. It backs light/dark persistence and the library cannot function without it. Install it first.

Installation

  1. Install TrueShade from Forge.
  2. Install Neo Design System.
  3. In your application, add NeoDesignSystem and TrueShade as dependencies.
  4. Set NeoBase as your application's theme.
  5. Add the ThemePaint script to your application, as described under Dark mode without the flash. It is optional, but without it a reload in dark mode shows the light theme for about a third of a second.

That is the whole setup. There is no OnApplicationReady hook to wire, no body class and no data attribute to set by hand. AppShell handles all of it.

Building your first screen

AppShell is the outermost wrapper. It takes no input parameters and self-initialises: its OnReady places the TrueShade block and starts the shell for you.

  1. Place AppShell on your screen. It gives you three placeholders: Header, Aside and Content.
  2. Put ShellHeader in the Header placeholder.
  3. Put ShellAside in the Aside placeholder.
  4. Put Layout_Neo in the Content placeholder.
  5. Build your page inside Layout_Neo's Content placeholder.

Do not call InitShell yourself when using AppShell. It is already called on ready with the aside expanded.

ShellHeader placeholders: Portfolio, PortfolioOverlay, ExpandToggle, Buttons, AdditionalBlocks, Avatar, LoginOverlay.

ShellAside placeholders: Primary, Secondary, HeaderIcon, HeaderIconLeft, HeaderTitle, HeaderIconRight. Input: SecondaryOpen (Boolean, default True).

Layout_Neo placeholders: Header, TopInfo, Content. Inputs: ScrollType (Text, default "page"), LayoutType (Text), ReserveSidePanelSpace (Boolean).

Building a sign-in screen

Layout_Login is the whole login composition in one block: a centred form column with theme-aware corner artwork, spaced and typed for you in light and dark. Use it on a public screen instead of AppShell, not inside it.

It takes no input parameters and gives you four placeholders:

  • Logo: your brand mark, or leave it empty and the theme paints a wordmark for the active theme. Fill it and the theme's mark switches itself off, so the two never overlap.
  • Title: heading or account line.
  • Content: your fields, submit button and inline actions.
  • Footer: the sign-up or secondary link line.

The form is yours, so the block imposes nothing on your authentication. Like AppShell, it places TrueShade itself, so the theme works on a login screen without any extra setup.

The same block carries the screens either side of sign-in. Reset password is Layout_Login with fewer rows and needs nothing extra. Sign up and verify email have a few classes of their own, below.

Password reveal. Add a container with pds-login-password-eye inside a field column marked pds-login-password-field and the icon is positioned, sized and themed. The toggle behaviour is yours to wire: the library ships the styling, not the logic. A few lines in the screen's OnReady that flip the input's type between password and text is all it takes.

Password requirements. For the verify-email step, password-analysis-title and password-analysis-requirements, with password-analysis-requirements-item on each line — a marker and a label, on a 4px rhythm. Put the list inside a field marked verify-password-field and it unrolls on :focus-within over 0.4s, so the rules appear while the field is being filled and fold away afterwards. Which requirements are met, and when, is your logic.

Consent row. verify-consent-row sets the checkbox-and-label rhythm: 12px type, an 8px gap, and the label free to wrap without dragging the checkbox out of line.

Error states. Add not-valid to a field for the invalid border. It survives hover and focus rather than losing the error colour to the interaction state.

Sidebar navigation

Build the sidebar inside ShellAside's Primary placeholder.

Use AsideItem for a navigation entry. Inputs: Label, IsActive, Level, IsOpen, HasChildren, HasIcon, ParentId, Section. It raises OnClick. Level 0 is a section header with an optional expand arrow; level 1 is a leaf link.

Use AsideSection for a collapsible group. It wraps an AsideItem header plus an animated grid that shows and hides its children. Inputs: Label, SectionId, IsOpen, IsActive, HasIcon, Section.

To control the sidebar from your own code, call ToggleAside. ShellAside adds the is-aside-expanded class to the body automatically.

Theme switching

Neo Design System ships light and dark. TrueShade persists the user's choice and applies it as a data-theme attribute on the root element.

  • SetTheme(Theme): apply "light", "dark" or "system-default".
  • GetTheme(): returns the scheme actually in effect. "system-default" is resolved to the real operating system preference, so you always get "light" or "dark" back.
  • ToggleTheme(): switch between light and dark.
  • UseSystemTheme(): follow the operating system preference.

AppShell and Layout_Login both expose an OnThemeChange event with two Text outputs: Raw (what the user selected, which may be "system-default") and Effective (what is actually rendered). Handle it when a component needs to react to a theme change, recolouring a chart for instance.

InitTheme exists only for backwards compatibility and does nothing once the theme system is initialised. Use AppShell instead.

Dark mode without the flash

The theme is applied by the shell once the screen renders, so a reload in dark mode briefly paints the light theme first. The ODC Portal avoids this with a small script that runs when the application starts, before any screen loads, and paints the page in the stored theme's colour. ThemePaint is the same script for Neo Design System.

  1. In your application, create a Script element named ThemePaint and paste the ThemePaint script into it.
  2. Select the application itself (the root of the tree, not a screen or block) and add ThemePaint to its Required Scripts.
  3. Publish.

It has to live in your application because a library cannot share scripts with the applications that use it, which is also why each ODC Portal application carries its own copy. Attaching it to a screen or block instead does not work: those scripts run when the block renders, which is after the page has already painted.

The script reads the same stored preference as TrueShade, follows the operating system when the choice is system default, and hands control back to the stylesheets on its own once the theme is applied, so there is nothing else to wire.

Styling standard widgets

Most of Neo's surface is CSS classes applied to standard OutSystems widgets, not blocks. Apply these to get Neo styling:

  • Button: btn. Variants: btn btn-primary, btn btn-destructive, btn btn-ghost.
  • Input: form-control. Add not-valid for the validation error state.
  • Checkbox: checkbox. Also takes not-valid. It stays the same size at every breakpoint rather than growing on touch widths.
  • Dropdown or Select: dropdown, on an element carrying the data-dropdown attribute. Variants: dropdown-small, dropdown-large, dropdown-ghost, dropdown-btn.
  • Table: table on the table, table-header on the header row, table-row on data rows.

Dialogs

A dialog is CSS rather than a block, so build it from standard widgets and apply these classes:

  • popup-dialog on the full-screen overlay that centres the card, with popup-background for the dimmed backdrop. Size it with popup-dialog-medium or popup-dialog-large.
  • popup-content on the card itself.
  • popup-dialog-header, with popup-dialog-header-title, popup-dialog-header-sub-title and popup-dialog-header-close.
  • popup-dialog-footer for the button row.
  • popup-dialog-scrollable when the body scrolls, popup-has-tabs with popup-tabs-header for the tabbed variant, and the popup-dialog-dirty-shield and popup-dialog-dirty-footer pair for an unsaved-changes confirmation.

As with the password reveal, the library ships the styling. Opening, closing and what the buttons do are yours.

Ready-made blocks

Beyond the shell, Neo Design System ships:

  • Layout_Login: the sign-in layout described above.
  • LayoutHeader: the page header.
  • Avatar: user initials in a coloured circle or square. Inputs: Initials (mandatory), Color, Format, Size, Label.
  • Badge: status badge with semantic colour variants. Inputs: Label (mandatory), Variant (default "neutral").
  • SearchInput: a search-styled input.
  • Pagination: page navigation, with keyboard and screen-reader support.
  • DropdownField: a searchable dropdown field. It opens on focus and puts the caret in its search box, so arrow keys, type-ahead and Enter behave the way they do elsewhere; Tab moves on to the next field rather than into the option list, and Escape closes it. Searching for something absent shows a two-line empty state. Unlike most of the library it ships behaviour as well as styling: all 13 OutSystemsUI/Dropdowns client actions work against it, so DropdownSetValue, DropdownClear and the rest do what they do on the stock widget. Takes OptionalConfigs (AllowMultipleSelection, IsDisabled, NoResultsText, SearchPrompt, NoOptionsText, SanitizeDropdownValues).
  • DropdownEmpty and DropdownItem: a floating menu panel and its rows. Keyboard and screen-reader accessible, dismisses on click-outside and on Escape, and positions itself to stay inside the viewport. DropdownEmpty inputs: IsOpen, PopoverWidth, ExtendedClass, TriggerLabel, with Trigger and Content placeholders. DropdownItem input: Title (mandatory).
  • Skeleton, SkeletonBox and SkeletonTable: loading placeholders.
  • Section: a content section wrapper.
  • Icon and IconSprite: the icon set.

Using design tokens

Neo Design System defines 612 design tokens covering colour, typography, spacing and sizing, elevation, motion and layout, with 295 dark-mode overrides.

Reference them from your own CSS with var(--token-name) rather than hardcoding values. Anything built on the tokens stays correct in both light and dark, and follows the design language when it moves. Tokens are the intended extension point: if a component you need does not ship as a block, build it against the tokens and it will match everything else.

The login layout adds four of its own that you can override the same way: --login-text-primary, --login-text-secondary, --login-label, --login-link-hover.
